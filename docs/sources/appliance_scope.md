## c) 경로 후보

### P1 반복 하자 → 교환·환불 요건 체크리스트 (금액 계산 없음)

- 근거 **[원문]**: 별표 Ⅱ ① 3) "품질보증기간 이내 … 수리불가능 시1) → 제품교환 또는 구입가 환급"과 각주 1) "품질보증기간 이내에 동일하자에 대해 2회까지 수리하였으나 하자가 재발하는 경우 또는 여러 부위 하자에 대해 4회까지 수리하였으나 하자가 재발하는 경우는 수리 불가능한 것으로 봄."
- 하는 일: 사용자 응답으로 요건을 하나씩 확인하고, 모두 충족되면 "기준상 제품교환 또는 구입가 환급으로 정해져 있다"는 해결기준 문구와 원문 카드를 보여 준다. 금액은 화면에 내지 않는다. "구입가 환급"의 금액은 사용자가 입력한 구입가 그대로라 계산이 아니지만, 이 경로에서는 표시하지 않는 것을 기본으로 둔다 **[제안]**.
- 요건 체크리스트 **[제안]** (각 항목 예 / 아니오 / 모름):
  1. 지원 품목인가 (별표 Ⅲ 행, Q-A7)
  2. 정상적인 사용 상태에서 생긴 성능·기능상의 하자인가 (사용자 응답, 엔진은 판정하지 않음, Q-A8)
  3. 수리가 품질보증기간 안에 있었는가
  4. 동일 하자 수리 2회(또는 여러 부위 4회)를 했는가
  5. 그 뒤 하자가 재발했는가
- 3번을 날짜로 계산할지, 사용자 응답으로 받을지가 결정이다. 날짜로 계산하면 기산일(시행령 별표 1 4.라·마), 보증서 기간 우선(4.가·나), 만료일 계산(Q-A5)이 필요하다. 응답으로 받으면 원문 확인이 줄지만 사용자가 보증기간을 모를 수 있다 (→ e) 결정 1).
- 배지 **[제안]**: 모든 요건이 "예"이고 쓰는 블록이 `verified: true`이면 ✅ (금액이 없으므로 해석 의존 계산이 없다). "모름"이 하나라도 있으면 🔍. "아니오"이면 이 경로의 해결기준이 적용되지 않는다는 안내와 다른 해결기준(무상수리 등) 문구. 4번 횟수의 합산 방식(여러 부위 4회를 전체 합산으로 볼지)은 원문이 정하지 않았다 **[해석, Q-A8]** → 경계에서는 🔍.
- 블록: `resolution_table`, `repair_impossible_rule`, `items`(보증기간), 날짜 계산을 하면 시행령 별표 1 4. 관련 블록.
- 장점: 숫자를 만들지 않아 절대 규칙 1의 위험이 없고, Q-A1·Q-A2·Q-C1(감가·10% 가산·원 미만)에 막히지 않는다.

### P2 보증기간 경과 후 부품 미보유 → 정액 감가상각 잔액 + 구입가 10% 가산

- 근거 **[원문]**: 별표 Ⅱ ① 5) "부품보유기간 이내에 수리용 부품을 보유하고 있지 않아 발생한 피해 … 품질보증기간 경과 후 → 정액 감가 상각한 잔여 금액에 구입가의 10%를 가산하여 환급", 비고 "감가상각방법：정액법, 내용연수는 별표Ⅳ 품목별 내용연수표(월할계산) 적용 / 감가상각비 계산：(사용연수/내용연수)×구입가 / 감가상각 잔여금 계산：구입가-감가상각비".
- 계산식 (명세 초안 A5): `잔여금 = 구입가 − 구입가 × 사용개월 ÷ 내용연수개월`, `환급 = 잔여금 + 구입가 × 10%`. 5)는 "잔여 금액에 구입가의 10%"로 문구가 명시돼 있어 3)·4)의 10% 가산 모호성(Q-A2)이 없다 **[원문]**.
- 원문에 없어 결정이 필요한 것: 사용개월의 시작·끝·1개월 미만 처리(Q-A1), 내용연수 년→월 환산(Q-A3), 원 미만 처리(Q-C1), 부품보유기간을 넘긴 뒤 처리(Q-A6, 각주 2)가 5)에도 걸리는지), 별표 Ⅳ에 없는 품목(Q-A4), 한도(4)에만 "(한도：구입가격)", 5)에 적용할지 원문에 없음. 사전 조사 기계 확인: 잔여금 + 0.1 × 구입가 > 구입가 ⇔ 사용개월/내용연수 < 0.1).
- 배지: 사용개월 결정이 원문에 없으므로 세탁과 같은 결정 민감도 검사(대안 조합을 다시 계산해 금액이 같을 때만 ✅)를 둘지 결정이 필요하다 **[제안]**. 두지 않으면 계산 결과는 항상 해석 의존 🔍이다.
- 요건 판정(부품 미보유 여부, 부품보유기간 이내 여부, 품질보증기간 경과 여부)은 사용자 응답 또는 날짜 계산이 필요하다. 부품보유기간 기산점이 "제조일"(별표 Ⅲ 머리 주석)이라 제조일 입력이 더 필요하다 **[원문]**.
- 블록: `depreciation`, `lifespan_rule`, `items`(부품보유기간), `resolution_table`.

## f) 케이스 도출 계획

세탁 R1·R2와 같은 방식으로 한다.

1. 결정(e)의 답을 받은 뒤, 엔진 코드를 열지 않는 독립 검증 1회로 원문 표(HWPX 경로, PDF 경로)에서 계산기 두 개를 따로 만든다. 스크립트는 저장소 밖에 두고, 저장소에는 보고서(`docs/sources/appliance_cases_p1.md` 등)만 남긴다.
2. P1 케이스 (요건 조합): 모든 요건 충족 / 동일 하자 2회 + 재발 / 동일 하자 1회 + 재발(미충족) / 여러 부위 4회 + 재발 / 여러 부위 3회 + 재발 / 재발 없음 / 보증기간 경과 / 정상 사용 "아니오"·"모름" / 지원 밖 품목(스마트폰 등 ❔) / 승패 질문 ❔ / 필수 누락 🔍. 날짜 계산(e-2 (b))을 고르면 보증기간 만료일 전날·당일·다음 날, 보증서 기간이 더 긴 경우, 판매일 미상(제조일 + 3월)을 더한다.
3. P2 케이스 (금액): 사용개월 경계(1개월 미만, 정확히 n개월, 말일), 내용연수 끝 근처(Q-A6), 10% 가산이 구입가를 넘는 구간(사용개월/내용연수 < 0.1), 원 미만 내림·half up 차이, 별표 Ⅳ에 없는 품목, 업체 제시액 ⚠️.
4. 기존 `appliance_cases_draft.md` 10건 중 같은 상황은 재사용 여부를 표시하고, 기대값은 결정 반영 후 두 계산기 결과로 다시 적는다.
5. 각 케이스에 기대 배지, 사유 코드, 인용 ID, 화면 한 줄을 적고 "승인 대기"로 낸다. 승인 전에는 테스트 기대값으로 쓰지 않는다.
6. 사용자 표본 대조 시트(`user_check_sheet.md` 형식)에 P1·P2 항목을 추가해 블록 `verified` 판단(e-8)에 쓴다.
