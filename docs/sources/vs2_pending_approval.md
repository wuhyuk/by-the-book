## 1. 스펙에 문구가 없어 초안을 넣은 항목

### 1.1 ❔ 판단 불가 사유의 화면 한 줄 (7건)

MVP_SPEC 5.4 표에는 🔍·⚠️ 사유의 화면 한 줄만 있고, 5.2 순서 1~8의 ❔ 사유 문구는 없다. `UNSUPPORTED_INDUSTRY`는 10절 문구("아직 지원하지 않는 업종입니다. 1372에 문의하세요")를 그대로 써서 제외했다.

| 코드 | 초안 |
|---|---|
| `JUDGMENT_REQUESTED` | 승패나 법적 효력에 대한 판단은 이 서비스에서 하지 않습니다. 아래 상담 창구에 문의해 주세요. |
| `ACADEMY_LAW` | 학원법 시행령이 적용되는 계약은 이 기준(고시)의 적용 대상에서 빠져 있어 계산하지 않았습니다. |
| `WITHDRAWAL` | 청약철회로 해지하는 경우에는 이 기준(고시)이 적용되지 않아 계산하지 않았습니다. |
| `BUSINESS_FAULT` | 사업자 사정으로 해지하는 경우는 아직 지원하지 않습니다 (다음 확장 예정). |
| `FORCE_MAJEURE` | 천재지변 등 불가항력으로 해지하는 경우는 아직 지원하지 않습니다. |
| `PERIOD_UNDER_28_DAYS` | 계약 기간이 1개월보다 짧아 이 기준(계속거래)의 적용 대상인지 확인할 수 없어 계산하지 않았습니다. |
| `NO_REFUND_LIMIT_CLAUSE` | 계약서에 중도 해지 시 환급 제한이나 위약금 조항이 없다고 답해 이 기준(계속거래)의 적용 대상인지 확인할 수 없어 계산하지 않았습니다. |

- `BUSINESS_FAULT`의 "다음 확장 예정"은 10절 UX 메모를 따랐다. `FORCE_MAJEURE`는 5.2에서 "확장 후보"라서 예정이라고 쓰지 않았다.
- `PERIOD_UNDER_28_DAYS`·`NO_REFUND_LIMIT_CLAUSE`는 "적용되지 않는다"고 단정하지 않고 "적용 대상인지 확인할 수 없어"로 썼다 (표현 가드레일).

### 1.2 권고 기준 고지 (`DISCLAIMER`)

> 이 결과는 공정거래위원회 고시 등 기준에 정해진 내용을 정리한 참고 정보입니다. 기준상 이렇게 정해져 있다는 뜻이며, 실제 환급 여부나 금액을 확정하지 않습니다.

- **질문 Q1**: CLAUDE.md 절대 규칙 5는 "소비자분쟁해결기준은 법적 구속력이 없는 권고 기준"이라고 적고 있다. 그런데 헬스장 계산의 근거는 소비자분쟁해결기준이 아니라 별도 고시 「계속거래 등의 해지·해제에 따른 위약금 및 대금의 환급에 관한 산정기준」(공정위 고시 제2019-9호)이다. 이 고시의 구속력은 원문으로 확인하지 않았다. 그래서 초안에 "법적 구속력이 없는 권고 기준"이라는 말을 넣지 않았다. 고지에 그 표현을 넣을지, 넣는다면 어느 원문을 근거로 할지 정해 주세요.

### 1.3 상담 창구 안내 (`CONSULT_MESSAGE`, `CONSULT_CHANNELS`)

- 문구: "이 결과는 아래 상담 창구에 문의해 주세요."
- 창구: `1372` / `한국소비자원 피해구제` / `대한법률구조공단 ☎132` (5.2 머리말 표기 그대로)
- 표시 조건: 배지가 ❔이거나 계산하지 않은 🔍(`MISSING_REQUIRED`·`INVALID_INPUT`·`NOTICE_AFTER_VALIDITY`)일 때 (5.5 부여 규칙 "❔·계산 안 함 🔍의 상담 창구 안내").
- 링크 URL은 넣지 않았다. 10절에 따라 공식 페이지 확인 후 단계 6(지금은 VS2 화면 PR 또는 VS5)에서 넣는다.
- **질문 Q2**: `MISSING_REQUIRED`·`INVALID_INPUT`은 다시 입력하면 해결되는 경우가 많다. 5.5 문장을 글자 그대로 따라 이 두 코드에도 상담 창구를 붙였다. 이 두 코드에서는 빼는 쪽이 낫다면 알려 주세요.

## 2. 스펙 문구를 그대로 쓴 항목 (5.4·5.5 "초안, 사용자 검토 대상")

`gym_display.py`의 `_SPEC_FLAG_TEXTS`(🔍·⚠️ 16건), `NOTICE_TEXTS`(10건), `WITHDRAWAL_GUIDE`는 MVP_SPEC 원문과 글자 단위로 같다. `tests/test_gym_display.py`가 이를 고정한다. 기존 결정대로 5.4·5.5 문구 검토도 이 보고서로 받는다.

- `POSTPONEMENT_INPUT`은 결과 화면용 문구("연기 기간이 있으면 결과가 달라질 수 있습니다.")만 넣었다. 입력 안내 문구("이용을 연기했다면 종료일에는 연장된 종료일을 입력해 주세요.")는 폼 PR(2-2)에서 쓴다.
- `PT_ONLY_QUESTION`("PT만 계약하셨나요?")은 입력 단계 질문이라 엔진은 내지 않는다. 문구 누락 검사 때문에 표에만 둔다.

## 3. 합리적 기본값으로 진행한 결정 (PR 2-1)

| 항목 | 기본값 | 이유 |
|---|---|---|
| 요청 본문 검증 | 라우터가 본문을 그대로 읽어 `GymInput.model_validate_json`으로 검증한다 | `GymInput`은 strict 모델이다. FastAPI 기본 검증(파이썬 모드)은 날짜 문자열 `"2026-01-01"`도 거부한다. JSON 모드는 ISO 날짜를 받고, `"100"` 같은 숫자 문자열은 계속 거부한다. OpenAPI 문서에는 `GymInput` 스키마를 따로 적었다 |
| 응답 형태 | `{"result": GymResult, "display": GymDisplay}` | 8.1 VS2 기본값 ("`GymResult` + 표시용 정보"). `result`는 엔진 출력과 같다 |
| 422 응답 | `{"message": 고정 문구, "detail": [{"loc", "type"}]}` | 입력값(`input`), `ctx`, `msg`, `url`을 뺀다 |
| 500 응답 | `{"message": 고정 문구}`. 로그에는 예외 종류 이름만 | 기본 처리는 추적 정보를 로그에 남기고, 예외 메시지에 입력값이 들어갈 수 있다 |
| 규칙 파일 로드 | 요청마다 `load_rule("gym_refund")` | 단순함 우선. 캐시는 성능 문제가 보일 때 |
| 표시 정보 위치 | `rules/gym_display.py` (사용자 승인 2026-11-06). VS4에서 공통 표시 패키지로 합칠지 판단 | |
