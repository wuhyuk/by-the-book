### L22. 업체 제시액이 4조합 최솟값과 같음 (신규 제안, 승인 대상)

## 6. 불일치·열린 질문

불일치: **없음** (원문 경로 1 ↔ 2, 계산기 A ↔ B, 계산 ↔ 초안, 원문 ↔ 규칙 JSON).

열린 질문 (명세 모호점. 규칙을 지어내지 않고 질문으로 둔다):

- **Q1 `NO_RECEIPT_LOSS` 입력 없음.** 조건이 "분실이고 인수증 미교부"인데 명세 L1에 인수증 교부 여부 필드가 없다. 분실 케이스(L5, L6)에서 이 안내를 붙일지 정할 수 없다. 선택지: (a) 입력 필드 추가(예: `receipt_issued: bool | None`, `False`일 때만 안내) (b) 분실이면 조건부 문구로 항상 안내 (c) 안내 코드 삭제.
- **Q2 안내 코드 부여 범위.** 세탁 명세 L5에 "계산한 결과에만 붙인다"는 규칙이 없다. 이 보고서는 헬스장 5.5 규칙을 준용해 계산한 결과에만 붙였다 [해석]. 초안은 L1·L5에만 안내를 적었다. 승인 시 L2·L3·L6·L8·L13~L15의 안내(4절)도 기대값에 넣을지 정해 주세요.
- **Q3 입증 불가(20배)일 때 `OFFER_BELOW_STANDARD_MIN`.** 비교 기준이 "4조합 최솟값"인데 20배는 조합이 없다. 계산기는 20배 금액과 비교했다 [해석]. 케이스는 없다.
- **Q4 내용연수가 한 값인 행에 `variant_key`가 들어오면.** 한복류는 소재 칸이 둘이지만 값은 하나라 `variant_key`가 필요 없다고 봤다 [해석] (L20은 넣지 않음). 그런데 입력 검증 "`variant_key`가 해당 행 후보에 없음"을 문자 그대로 적용하면, 한복에 소재(예: 견)를 넣은 입력이 `INVALID_INPUT`이 될 수 있다. 무시할지 오류로 볼지 정해 주세요.
- **Q5 입력 검증 "금액 ≤ 0"의 범위.** `provider_offer = 0`(업체가 배상 거부)을 입력 오류로 볼지 불분명하다. 계산기는 구입가격·세탁요금·제시액 모두 ≤ 0이면 `INVALID_INPUT`으로 처리했다. 해당 케이스는 없다. 순서 2(무인세탁소)와 입력 검증 목록은 명세상 아직 **[제안]**이라 L16·L19는 명세 확정에 따라 바뀔 수 있다.
- **Q6 두 원인 메시지의 비율 표시.** L4.1 "사용일수 산입과 원 미만 처리" 형식에는 "a%에서 b%로"가 없다. `sensitivity_ratio_alt`(L21은 80)는 채워지지만 화면에 나오지 않는다. 형식 그대로 둘지 확인해 주세요 (L21 기대 메시지는 현재 형식 기준).
- (기존) Q-L11 사용일수 D0 − 1 검사 여부: 넣으면 L6가 ✅ → 🔍(10%→20%, 100,000~200,000)로 바뀐다. 이 보고서는 현재 명세(검사 안 함)로 계산했다.
