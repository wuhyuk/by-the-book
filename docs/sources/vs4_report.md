## 4. 남은 위험

- 케이스가 승인되기 전에는 세탁 금액을 고정하는 테스트가 없다 (원문 표 값·기준 계산기 비교·구조 테스트만 있다). 승인 뒤 케이스 테스트를 넣어야 회귀가 막힌다.
- 표본 대조(`user_checked`) 전이다. 블록 `verified: true`는 기계 대조 근거다.
- 실제 Gemini로 세탁 문장을 추출해 보지 않았다 (키 없이 가짜 LLM). 예/아니오 단서 규칙은 사람이 쓴 낱말 목록이라 놓치는 표현은 되묻기로 간다 (채택하지 않음). VS5 평가의 되묻기 비율로 잰다.
- [미결] Q-L11 (사용일수 D0 − 1 검사), 세탁 표준약관 두 번째 경로 확인(Q-L7) 전이라 표준약관 조항은 인용하지 않는다.
- 결과 화면의 고지는 계산하지 않은 ❔ 결과에도 나온다 (헬스장과 같은 동작).
- 문장 분석은 사용자가 "모름"으로 둔 예/아니오와 "세트 아님"을 빈 값으로 보고 문장 값으로 채운다 (헬스장 결정 B와 같은 동작).
- `/api/calculate` OpenAPI 응답 스키마가 헬스장·세탁 합집합(anyOf)으로 바뀌었다. 요청 본문 스키마와 실제 응답은 그대로다.
