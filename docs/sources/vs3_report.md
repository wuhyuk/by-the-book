| 항목 | 내용 |

| 안 | `/api/guide`(설명 문장·업체용 요약 문안·다음 행동 + 인용 검증, 절대 규칙 7)를 VS3 PR에 함께 넣는다 |

| 판단 | 당기지 않는다 |

근거:

1. **VS3 PR이 이미 크다.** 어댑터·마스킹·추출 스키마·근거 확인·가드레일·되묻기 화면·모델 비교가 들어 있다. 여기에 생성 문장(설명·업체 문안)까지 넣으면 한 PR이 "추출"과 "생성" 두 목표를 갖게 된다 (CONTRIBUTING: 브랜치 하나는 하나의 논리적 목표).
2. **핵심 흐름은 guide 없이 끝까지 돈다.** 문장 → 추출 → 폼 확인 → 엔진 계산 → 결과 카드(배지·사유·근거 조항 원문·출처·고지)가 VS2 표시 정보로 이미 나온다. guide는 설명을 덧붙이는 기능이고, 빠져도 MVP 완료 기준(7절) 중 막히는 항목이 없다.
3. **승인할 문구가 많다.** 업체용 문안은 CLAUDE.md "업체용 요약 문안 가이드"의 금지 표현 검사가 필요하고, 생성 예시를 사용자가 승인해야 한다. VS3 비교 실험 결과(모델 선택)가 나온 뒤에 프롬프트를 쓰는 편이 다시 쓰는 일이 적다.
4. **무료 한도를 나눠 쓴다.** guide는 계산마다 LLM을 한 번 더 부른다. 한도 수치를 아직 확인하지 못했으므로(1.2) 추출만 먼저 운영해 본다.

## 1. Gemini 공식 문서 확인 (2026-11-08)

`ai.google.dev` 문서는 모두 같은 경로의 `aistudio.google.com/docs/...`로 이동(301)한다. 아래는 이동한 페이지에서 읽은 내용이다.

### 1.1 모델

| 모델 코드 | 상태 | 입력/출력 토큰 한도 | 구조화 출력(Structured outputs) | 출처 |
|---|---|---|---|---|
| `gemini-3.5-flash` | **폐기(deprecated)**. "Gemini 3.5 Flash (`gemini-3.5-flash`) is deprecated and has been replaced by Gemini 3.6 Flash (`gemini-3.6-flash`)." / "API requests to `gemini-3.5-flash` are automatically routed to `gemini-3.6-flash`." | 1,048,576 / 65,536 | 지원 | https://aistudio.google.com/docs/models/gemini-3.5-flash |
| `gemini-3.1-flash-lite` | Stable | 1,048,576 / 65,536 | 지원 | https://aistudio.google.com/docs/models/gemini-3.1-flash-lite |

→ 9절 확정 4의 기본 후보 `gemini-3.5-flash`로 보낸 요청은 실제로는 `gemini-3.6-flash`가 처리한다. 사용자가 11-06에 확인한 200 응답과 모순되지 않는다 (자동 전달). 모델 선택은 3절 A1에서 묻는다. 코드에는 모델 이름이 없고 `LLM_MODEL`과 비교 스크립트 인자로만 정하므로, 어느 쪽을 골라도 코드는 바뀌지 않는다.

### 1.2 무료 한도

- 한도 페이지(https://aistudio.google.com/docs/rate-limits)에는 모델별 RPM·TPM·RPD 숫자가 **없다**. "Rate limits depend on a variety of factors (such as your usage tier) and can be viewed in Google AI Studio." / "Rate limits are applied per project, not per API key." / "Specified rate limits are not guaranteed and actual capacity may vary."
- 요금 페이지(https://aistudio.google.com/docs/pricing): `gemini-3.1-flash-lite` 무료 등급은 입력·출력 "Free of charge", **"Used to improve our products: Yes"**. `gemini-3.5-flash` 행은 이번에 읽은 범위에 없었다.
- 429: "If you hit a spend-based rate limit, the API returns a `429 RESOURCE_EXHAUSTED` error." RPM·RPD 초과의 상태 코드는 문서에 적혀 있지 않다. 구현은 429를 한도 초과로 처리하고 나머지 4xx·5xx는 일반 실패로 처리한다.

→ 실제 한도는 사용자가 AI Studio에서 확인했다 (4.2). 앱과 비교 스크립트의 호출 간격은 그 값으로 정했다.

### 1.3 구조화 출력 (REST `generateContent`)

- 엔드포인트: `POST https://generativelanguage.googleapis.com/v1beta/models/{model}:generateContent` (https://aistudio.google.com/api-reference/generate-content).
- `generationConfig.responseMimeType = "application/json"`, 스키마는 `responseJsonSchema`. 참조 문서의 다른 스키마 필드 설명: "Use `responseJsonSchema` rather than this field."
- null 허용: "include `"null"` in the type array (e.g., `{"type": ["string", "null"]}`)". `enum`, `required`, `format: date`, `minimum`을 지원하고 `anyOf`도 예시에 있다 ("simplify `anyOf` unions"). minLength·maxLength 등은 무시된다.
- 구현: 숫자·문자·불리언은 `["…", "null"]` 타입 배열, 범주 값(`refund_basis` 등)은 `anyOf: [{string, enum}, {null}]`로 둔다. 모든 키를 `required`로 둬서 모델이 null을 명시하게 했다 → `refund_basis`의 null(말하지 않음)과 `"unknown"`(모른다고 말함)을 스키마에서 구분한다.
- 키 전달: 문서의 `generateContent` 예시는 `?key=` 쿼리를 쓰고 `x-goog-api-key` 헤더는 Interactions API 예시에 나온다. 구현은 **헤더**를 쓴다 (URL에 키가 있으면 httpx 로그·예외 메시지에 URL이 찍힐 수 있다). 헤더 방식이 `generateContent`에서 동작하는지는 사용자의 실제 호출(4절)로 확인한다.

### 1.4 temperature와 thinking

- https://aistudio.google.com/docs/whats-new-gemini-3.6: "`temperature`, `top_p`, and `top_k` are deprecated. The API ignores these parameters and returns an error in future model generations." / "**Remove these parameters from all requests.**"
- 참조 문서: temperature "is no longer supported and is silently ignored on Gemini 3.6 Flash and newer models."
- `gemini-3.1-flash-lite`의 temperature 처리는 문서에 적혀 있지 않다.

→ **스펙(temperature 0)과 제공자 권고가 다르다.** 지금은 스펙대로 `temperature: 0`을 보낸다. 3.6 Flash(= 3.5 Flash 요청)에서는 무시되고, "future model generations"에서는 400이 될 수 있다. 결정은 3절 A3. 결정성은 temperature 대신 시스템 지시·few-shot·JSON 스키마 강제와 코드 쪽 근거 확인으로 확보한다.
- thinking: `generationConfig.thinkingConfig.thinkingLevel` (MINIMAL/LOW/MEDIUM/HIGH), 기본값은 모델마다 다르다. 이번 구현은 설정하지 않는다 (기본값). 응답 시간이 길면 비교 결과를 보고 정한다.

## 2. 구현 요약

### 2.1 흐름

```text
문장 ─ mask_pii ─┬─ 규칙 가드레일(정규식) 걸림 → ❔ 판단 불가 + 상담 창구 (LLM 호출 안 함)
                 └─ LLMClient(Gemini, JSON 스키마, temperature 0, few-shot 4건)
                      → RawExtraction 스키마 검증 (실패 → 502 고정 문구)
                      → 근거 확인: 근거 구절이 마스킹된 문장에 그대로 있고,
                         금액·횟수·날짜는 그 구절을 코드가 읽은 값과 같을 때만 채택
                      → LLM 판단 플래그(근거 구절 확인)면 ❔
                      → fields(확인된 값) / unverified / missing(5.1 필수 열)
화면: fields로 폼을 채우고 missing·unverified를 폼에서 다시 묻는다
      → 사용자가 확인 → /api/calculate (GymInput strict 검증) → 엔진
```

### 2.3 기본값으로 진행한 설계 (승인 대기, 3절 B)

|---|---|---|

### 4.5 Q12 `is_withdrawal`: 근거 확인을 통과한 이유와 수정 (D1, 2026-11-08 구현)

- **원인**: 근거 확인(`llm/extraction.py` `_grounded`)은 금액·횟수·날짜만 그 구절에서 코드가 읽은 값과 대조한다. 예/아니오 필드는 근거 구절이 문장에 있기만 하면 통과한다. Q12 문장의 "…청약철회 기간은 지났어요"를 근거로 `is_withdrawal`에 값을 넣으면 채택된다 (기대값은 null). 스크립트는 값을 출력하지 않으므로 `true`였는지 `false`였는지는 모른다.
- **엔진까지 도달하는가: 예.** 경로는 `mergeExtraction` → 폼 체크박스 "청약철회로 해지" → `buildInput` → `/api/calculate` → 엔진이다.
  - `false`이면 기본값과 같아 결과에 영향이 없다.
  - `true`이면 체크박스가 켜지고, 그대로 제출하면 엔진이 ❔ `WITHDRAWAL`(계산 안 함)을 낸다. 잘못된 금액은 나오지 않지만 계산해야 할 사례가 계산되지 않는다.
- **폼 단계에서 걸러지는가**: 시각적으로만 걸러진다. 칸 아래에 "문장: “청약철회 기간은 지났어요”"가 보일 뿐이고, 따로 확인을 요구하지 않는다.
- **재현**: 수정 전 코드에서 Q12 문장 + `is_withdrawal=true`/`false`(근거 "청약철회 기간은 지났어요") 둘 다 채택됨을 확인했다. 재현 테스트 `test_q12_is_withdrawal_not_adopted`를 먼저 쓰고(실패 확인) 고쳤다.
- **수정 (구현함, 사용자 추가 조건 반영: 단서 목록은 코드 상수 `BOOL_CUE_RULES`·`JUDGMENT_CUES`, 단서가 없으면 버리지 않고 되묻기 `unverified`)**:
  1. 결론을 바꾸는 예/아니오 필드에 단서 낱말 검사를 넣는다. `is_withdrawal`·`withdrawal_cleared`는 근거에 "철회", `academy_law_applies`는 "학원"이 있어야 한다. `is_withdrawal=true`인데 근거에 "지났"·"지나"·"아니"가 있으면 버린다.
  2. 기본값과 같은 `false`(`is_withdrawal`, `academy_law_applies`)는 정보가 없으므로 채택하지 않는다. 조용히 버리지 않고 되묻기로 보낸다.
  3. ❔를 일으키는 추출값은 근거 확인을 통과해도 "문장에서 이렇게 보입니다. 맞는지 확인해 주세요" 안내를 붙인다. 대상은 `is_withdrawal=true`, `academy_law_applies=true`, `termination_cause=business/force_majeure`, `industry=other`, `has_refund_limit_clause=false`다.
- **테스트 (`tests/test_llm_bool_cues.py`, 45건)**:
  - Q12와 같은 문장에서 `is_withdrawal=true`/`false`를 각각 낸 가짜 응답 → 둘 다 채택 안 됨.
  - "청약철회하려고요" + `true` → 채택되고 확인 안내가 붙음.
  - 학원 단서가 없는 `academy_law_applies=true` → 채택 안 됨.
  - `business` 해지 사유 → 확인 안내.

### 4.6 예/아니오 추출 필드 전수 점검 (D1)

모든 불리언 필드에 Q12와 같은 구멍(근거 구절의 뜻을 확인하지 않음)이 있었다. 근거 구절이 문장에 있기만 하면 값과 상관없이 통과했기 때문이다. 모두 같은 방식으로 막았다: 필드별 단서 낱말 + 값의 뜻 확인 → 실패하면 되묻기.

| 필드 | 값에 따른 엔진 영향 | 구멍 | 단서 (근거에 하나 이상) | 뜻 확인 |
|---|---|---|---|---|

## 7. 남은 위험

- **불리언 뜻 확인은 낱말 단위다 (D1 구현 후)**: 단서·부정 낱말로 뜻을 확인하므로 "환불 안 된다는 조항이 있어요"처럼 부정 낱말이 섞인 긍정 문장은 받지 않고 되묻는다 (안전한 쪽). 반대로 낱말은 맞지만 뜻이 다른 드문 문장은 통과할 수 있어, ❔ 값은 확인 안내를 붙이고 폼에서 사용자가 확인한 뒤에만 계산한다. 되묻기가 늘어 문장 분석의 편의가 줄 수 있다. 얼마나 느는지는 VS5 평가 30건에서 되묻기 비율(전체·항목별)로 잰다 (MVP_SPEC 8.1).
- **범주 필드 뜻 확인 없음**: `industry`·`termination_cause`·`contract_type`·`refund_basis`는 근거 구절 존재만 확인한다. ❔를 일으키는 값만 확인 안내를 붙인다.
- **모델 비교 표본이 작다**: 2차 실행에서 예비 모델 `gemini-3.5-flash-lite`의 품질은 기본 모델과 같았다 (근거 확인 후 128/129). 다만 15건이라 차이를 판단할 수 없고, few-shot과 겹치지 않는 문장은 8건(68/68)뿐이다. 이 실행은 D1 반영 전 코드라 D1 이후 품질과 되묻기 증가는 VS5 평가 30건에서 잰다.
- **재시도 대기**: 429 뒤 Retry-After가 20초 이하이면 기다렸다가 재시도하므로 문장 분석 응답이 길어질 수 있다 (화면은 "찾는 중…"). 20초를 넘으면 기다리지 않고 예비 모델 또는 안내로 넘어간다. Gemini가 Retry-After 헤더를 보내는지는 확인하지 않았다 (없으면 간격 제한만큼 기다린 뒤 재시도).
- **간격 제한은 프로세스 안에서만**: 서버를 여러 개 띄우거나 비교 스크립트를 동시에 돌리면 합쳐서 한도를 넘을 수 있다 (한도는 프로젝트 단위).
- **마스킹 누락**: 이름은 단서("이름은", "저는 …입니다", 성씨+씨/님)가 있을 때만 가린다. 단서 없는 이름, 주소, 차량번호는 가리지 않는다. 상시 문구로 입력하지 말라고 안내한다.
- **무료 등급 데이터 활용**: 보낸 문장이 Google 서비스 개선에 쓰일 수 있다. 상시 문구로 알린다 (A4). 외부 배포판은 VS5 TODO(문장 분석 끄기·카운터).
- **근거 확인의 한계**: 근거 구절에 값이 하나뿐이면 받으므로, 모델이 엉뚱한 한 구절을 고르면 통과한다. 그래서 폼에서 사용자가 확인한 뒤에만 계산하고 항목마다 근거 구절을 보여 준다.
- **가드레일 정규식**: 테스트 22건(판단 11, 아님 11) 밖의 표현에서 금액 질문을 막을 수 있다. 막혀도 폼 직접 입력은 된다.
- **비교 케이스 중복**: 4.4. VS5 평가는 겹치지 않는 문장으로 한다.
