## L3. 계산식

```text
[사용일수]  days = request_date − purchase_date          ← 구입 당일 의뢰 = 0일 (D0) [결정 2026-11-02 Q-L1]

[내용연수]  life = lifespan_table[item_key][variant_key]   (1~6년, 원문 표)
            한복류 → 4 (행 전체에 걸친 한 칸, 값 하나. 두 소재 모두 4) [원문 칸 구조 확인 2026-11-06 Q-L8]
[배상비율]  ratio = ratio_table[life] 에서 days가 속한 칸의 비율 (%)   ← 원문 표, 구간은 빈틈·겹침 없음

[기준 금액]
base   = purchase_price   (Set 전체면 1벌 가격, 6.①)
amount = floor(base × ratio ÷ 100)                     ← Fraction으로 곱한 뒤 한 번만 원 미만 내림 [결정 2026-11-02 Q-C1]

[입증 불가]  proof_available = False → amount = laundry_fee × 20   ← 원문 5-1.③, 정수라 반올림 없음

[감액]  계산하지 않는다 (원문에 금액·비율 없음). 사유 코드로만 표시.

[결정 민감도 검사]  L4
```

| 항목 | 내용 | 표시 |
|---|---|---|
| 산정식 | 배상액 = 물품구입가격 × 배상비율 | [원문] 1.① |
| 사용일수 정의 | 구입일부터 세탁의뢰일까지, 사용 여부 무관 | [원문] 배상비율표 하단 |
| 사용일수 첫날 산입 | 넣지 않는다 (D0 = 의뢰일 − 구입일). 표가 "0~"으로 시작해 구입 당일 = 0일이 표와 맞는다. 대안 D1(양끝 산입)은 민감도 검사에 쓴다 | [결정 2026-11-02 Q-L1], 근거는 [해석] |

## L4. 배지 결정

결정 순서는 헬스장과 같다 (CLAUDE.md 절대 규칙 3): ❔ → 🔍(계산 안 함) → ⚠️(강건) → 🔍(해석 의존·미검증·확인 필요) → ✅. `decide_badge`는 그대로 쓴다.

블록 단위 검증: 결과가 쓰는 블록은 `ratio_table`, `lifespan_table`, (20배면) `unproven_fallback`이다 (`set_allocation`은 복원 후보). 하나라도 `verified: false`이면 `RULE_UNVERIFIED`(🔍)가 붙고 ⚠️ 코드는 뺀다. 최상위 `verified`(현재 `false`)는 배지 판정에 쓰지 않는다. **2026-11-02 표 블록은 기계 대조 일치로 `verified: true`, `user_checked: false`** [결정 2026-11-02 Q-S2, 헬스장 선례].

사유 코드 구성 [결정 2026-11-02 Q-S1]: 공통 Enum과 품목별 Enum으로 나누고, 품목별 코드 집합·표시 우선순위는 명시 목록으로 둔다. **헬스장 코드 이름은 바꾸지 않는다.**

### L4.1 결정 민감도 검사 [결정 2026-11-02 사용자 지시]

원칙: ✅는 "해석에 의존하지 않는 기준 확인"이다. 원문에 없는 결정을 바꿔도 결과가 같을 때만 ✅를 준다.

#### 검토한 대안 (검사 대상)

| 결정 (`in_source: false`) | 결정 값 | 대안 값 (JSON `alternative`) | 원인 이름 (메시지용) |
|---|---|---|---|
| 사용일수 첫날 산입 (`params.use_days`) | D0 = 의뢰일 − 구입일 (구입일을 세지 않음) | D1 = D0 + 1 (구입일도 셈) | 사용일수 산입 |
| 원 미만 처리 (`params.rounding`) | 내림 | half up (반올림) | 원 미만 처리 |
| Set 일부 손상 (`params.set_partial_damage`) **[복원 후보]** | 7. 배분 | 1벌 전체 기준 (복원할 때만 검사) | Set 배분 |

한복류 내용연수(두 소재 모두 4년)는 2026-11-06 원문 칸 구조로 확인해 `in_source: true`가 되었으므로 결정이 아니다. 검사 대상에서 뺐고, 한복류 결과에 🔍를 항상 붙이던 보수적 기본값도 없앴다 **[결정 2026-11-06 Q-L8 지시]** (근거는 L3 표 "한복류 내용연수").

#### 검토하지 않은 대안 (검사 대상 아님)

아래는 원문에 정해져 있지 않거나 해석 여지가 있지만, 민감도 검사가 다시 계산하지 **않는** 방식이다. 이 목록은 2026-11-06에 확인한 범위이며 빠진 것이 있을 수 있다.

| 항목 | 검토하지 않은 대안 | 검사하지 않는 이유 | 영향 |
|---|---|---|---|
| 사용일수 | 양끝 모두 세지 않음 (D0 − 1) | 원문 "구입일로부터 … 세탁의뢰일까지"는 의뢰일까지 센다고 읽어 D0보다 짧게 세는 방식은 근거가 약하다 [해석] | 칸의 **첫날**에서 결과가 바뀐다. 예: L6(3,286일, 6년 행 10% 칸 첫날)은 D0 − 1이면 20% 칸 → 200,000원. 이 대안을 넣으면 칸 첫날 케이스(현재 L6)의 배지가 ✅에서 🔍로 바뀐다 |
| 사용일수 | 월·연 단위 환산 등 일수가 아닌 계산 | 원문 표가 일수 구간이다 | 없음으로 본다 |
| 원 미만 처리 | 올림, 10원 단위 처리 | 기준 금액을 과대 표시하지 않는 결정(내림)과 반대 방향이고, half up 하나로 "원 미만 처리에 따라 달라짐"을 이미 드러낸다 [결정 2026-11-02 Q-C1 취지] | 나머지가 1~49인 경우(내림 = half up)에도 올림이면 1원 커진다. 그 경우도 ✅가 나온다 |
| 물품구입가격 | 정가 대 실제 결제가 (할인·포인트·카드 할인) | 엔진은 사용자가 입력한 값을 쓴다. 어느 금액을 넣을지는 입력 안내의 문제다 | 금액 전체가 비례해 달라진다 |
| 품목·소재·용도 매핑 | 다른 행(예: 점퍼를 "스커트, 바지, 자켓, 점퍼" 대신 코트로) | 정보 추출 단계의 평가 대상이다 (엔진 입력은 확정 값) | 내용연수가 달라진다 |
| 혼방 소재 | 어느 소재 값을 쓸지 (예: 견 혼방 블라우스) | 입력 단계에서 사용자가 고른다 | 내용연수가 달라진다 |
| 감액·특약·면책 | 감액 금액 | 원문에 금액·비율이 없어 계산하지 않고 🔍 사유로만 표시한다 (L4.2) | 해당 사유가 있으면 이미 ✅가 아니다 |

**한계 [결정 2026-11-06 사용자 지시]**: 민감도 검사는 위 "검토한 대안"만 다시 계산한다. ✅는 "원문 값과, 나열한 결정을 나열한 대안으로 바꾼 모든 조합에서 결과가 같다"는 뜻이며, 나열하지 않은 해석(위 표 포함)까지 결과가 같다는 보장이 아니다. 새 대안을 검사 대상에 넣으려면 이 표·JSON `alternative`·케이스를 같이 고치고 사용자 결정을 받는다.

#### 검사 방법

1. 결정 값으로 계산한 결과를 **결과 값**으로 둔다 (`amount`).
2. 결과가 쓰는 결정마다 결정 값과 대안 값을 두고, **모든 조합**(지금은 D0·D1 × 내림·half up = 4가지)으로 다시 계산한다.
3. 각 조합의 **조회 결과(내용연수 행, 배상비율 칸)와 배상액**이 결과 값과 모두 같으면 통과다. 하나라도 다르면 🔍 `DECISION_SENSITIVE`를 붙이고, 결과 값은 그대로 보여 주되 아래 메시지 형식으로 원인과 범위를 적는다.
4. **원인 결정**: 그 결정 **하나만** 대안으로 바꿨을 때 결과가 달라지는 결정이다. 어느 결정도 혼자서는 결과를 바꾸지 않고 함께 바꿀 때만 달라지면 함께 바꾼 결정을 모두 원인으로 적는다.
5. 20배 계산은 결정을 쓰지 않으므로 검사 대상이 없다 (항상 통과).
6. 강건한 ⚠️ `OFFER_BELOW_STANDARD_MIN`은 4가지 조합 결과 중 **최솟값**과 비교한다 (헬스장 `OFFER_BELOW_B`가 가장 작은 해석과 비교하는 것과 같다).

미리 알 수 있는 성질 (검사 규칙이 아니라 케이스 설계용): 대안 D1은 D0보다 하루 많으므로, D0가 어떤 칸의 마지막 날(`max_days`)이면 칸이 바뀐다. half up은 `base × ratio`를 100으로 나눈 나머지가 50 이상이면 내림과 달라지고, 그 차이는 항상 1원이다.

#### `DECISION_SENSITIVE` 메시지 형식 [결정 2026-11-06 Q-L10]

코드 이름 `DECISION_SENSITIVE`는 수락되었다 (2026-11-06). 헬스장의 `INTERPRETATION_DEPENDENT`(단위대금처럼 **아직 정하지 않은** 해석)와 구분한다: 이 코드는 **정했지만 원문에 없는** 결정에 쓴다. 헬스장에 도입하면 공통 Enum 후보.

메시지에는 ① 원인 결정 이름(위 "원인 이름")과 ② 금액 범위(`sensitivity_min`원~`sensitivity_max`원)를 **반드시** 넣는다. 원인이 원 미만 처리 하나이고 범위 폭이 1원이면 "1원 차이"로 정확히 적는다. 원인 없이 "금액이 달라질 수 있습니다"만 쓰는 문구는 쓰지 않는다.

| 원인 | 화면 한 줄 형식 (초안, 사용자 검토 대상) | 케이스 |
|---|---|---|
| 사용일수 산입만 | "고시에 정해져 있지 않은 사용일수 산입 방식(구입일을 세는지)에 따라 배상비율이 a%에서 b%로 바뀌어, 기준 금액이 x원~y원으로 달라질 수 있습니다." | L2 (95%·80%, 40,000원~47,500원), L14 (70%·60%, 180,000원~210,000원) |
| 원 미만 처리만, 폭 1원 | "고시에 정해져 있지 않은 원 미만 처리(내림·반올림)에 따른 1원 차이가 있습니다 (x원~y원)." | L3 (61,728원~61,729원) |
| 사용일수 산입과 원 미만 처리 | "고시에 정해져 있지 않은 사용일수 산입 방식과 원 미만 처리에 따라 기준 금액이 x원~y원으로 달라질 수 있습니다." | (케이스 없음, 명세 확정 때 추가) |
| Set 배분 **[복원 후보]** | "세트 의류 일부 손상의 배분 방식(고시 7.의 비율 적용 여부)에 따라 기준 금액이 x원~y원으로 달라질 수 있습니다." | L4 (복원할 때) |

- 금액은 원 단위 정수, 천 단위 쉼표. 범위는 작은 값부터.
- `steps`에도 같은 원인과 범위를 한 줄로 남긴다.
- 문구의 숫자(비율·금액)는 엔진 결과 필드(`ratio_percent`, `sensitivity_ratio_alt`, `sensitivity_min`, `sensitivity_max`)에서만 채운다. LLM이 숫자를 만들지 않는다 (CLAUDE.md 절대 규칙 1).
